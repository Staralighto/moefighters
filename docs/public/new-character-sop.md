# 新角色开发 SOP（公开版）

本文描述在 moefighters 中新增一个可玩角色的标准流程。它只约定流程与验收标准，不规定具体实现手法——每个角色的技能表现、美术风格各不相同，按自己的习惯发挥即可。

流程分三步：**① 资料搜集 → ② 技能方案讨论 → ③ 制作与绘制**。三步都完成后角色才算"上线"。

---

## 第 0 步：开工前

先通读一份**已有角色**的实现（推荐挑一个近期加入的角色），确认自己理解：

- 角色数据在哪里定义、一个角色包含哪些字段（属性、被动、技能、外观引用等）；
- 精灵表的格子规格与用途（见下文第 3 步）；
- `npm run check` 会校验什么。

### 硬性约束（务必遵守）

- **不要改动精灵表格子规格**：公共表 8×3、技能表 4×3 的布局是引擎约定，所有角色共用。
- **不要整包重跑精灵表生成脚本**（`npm run sheets`）——它只会重画占位角色，重跑会覆盖已完成角色的成图。每个角色的表由各自的生成脚本产出。
- 精灵表 PNG 带有占位标记保护：脚本生成的占位图可以被覆盖，完成稿不会被脚本意外重写。生成脚本必须从共享的比例常量模块取缩放参数，不允许私设。

---

## 第 1 步：资料搜集

目标：把角色"是谁"搞清楚，为技能设计提供素材，而不是直接开始写代码。

1. 通读角色的百科词条（如萌娘百科），摘出：
   - 基本信息：代表色、身高发色瞳色、所属团体、担当乐器、学校学年；
   - **角色梗清单**：标志性口号、名场面、性格萌点、人际关系、外观记忆点，建议整理成表格（梗 / 来源 / 可技能化方向），供第 2 步讨论用；
   - 代表曲目与活动剧情（常被用作技能与特效命名）。
2. 注意版权边界：技能名、台词可以致敬原作梗，但素材（音频、图片）一律不引入仓库，美术全部自制。
3. 涉及真实人物（声优、中之人）的信息**不要**写进任何提交内容；词条中与企划角色无关的部分一律略去。

产出：一份梗表 + 一句角色的"定位一句话"（例如：贴脸爆发型 / 控场型 / 召唤型）。

---

## 第 2 步：技能方案讨论

目标：把梗表翻译成 6 个技能 + 1 个被动，先对齐方案再动手。

1. **确定定位**：角色数据按被动特质（ rush / focus / armor / beat 四类模板）取基础数值，先选定特质，再围绕它分配伤害、射程、速度、冷却。
2. **技能槽位**：每个角色恰好 6 个技能，绑定固定按键位（J K U I O L）。其中 4 个是"特写技能"（各自对应技能表中的一列），技能设计时应想清楚每个技能的三段演出（起手 / 生效 / 收招）大致是什么画面。
3. **对齐梗与机制**：每个技能最好有出处——口号、名场面、代表曲都可以。没有梗支撑的纯数值技能尽量少。
4. **评估实现成本**：新特效需要在渲染层特效表中新增条目；若技能需要超出常规表的专属演出（狂化形态、专用舞蹈/变身表等），提前说明，这类额外表是可选项，按需添加。
5. 与维护者过一遍方案（数值合理性、与其他角色的差异化、与 AI 对手的兼容性），定稿后再进入第 3 步。

产出：一页技能方案——6 技能的按键位、名称、类型、核心数值草案，以及每个技能对应的原作梗。

---

## 第 3 步：制作与绘制

### 3.1 数据接入

1. 在角色数据表中新增条目：ID（英文短名，同时是精灵目录名）、展示名、称号、登场台词、主题色、被动特质与数值、6 个技能、外观引用。
2. **将新 ID 加入可玩角色名单**——漏掉这一步角色不会出现在选人界面。

### 3.2 精灵表绘制

角色美术以程序化 SVG 生成、栅格化为 PNG 的方式制作，每个角色一个独立生成脚本。规格：

| 表 | 格子 | 内容 |
|---|---|---|
| 公共表 `common.png` | 8 列 × 3 行（每格 256×256） | 行 0：待机 / 奔跑 / 跳跃 / 格挡 / 闪避；行 1：受击 / 倒地 + 地面普攻三段；行 2：倒下定格 + 空中普攻三段 |
| 技能表 `special.png` | 4 列 × 3 行 | 列对应 4 个特写技能，行对应起手 / 生效 / 收招 |
| 可选：狂化表、专用演出表 | 同上述网格 | 按第 2 步方案决定是否需要 |

绘制建议：

- 先用脚本生成一套占位表跑通流程（跑动、出招、受击全部可动），确认技能手感后再出完成稿；
- 全部角色的体型比例共享一套常量，直接引用，不要在角色脚本里写死自己的数值；
- 需要超大道具/特效时，在共享的精灵视图模块中登记偏移常量，不要把偏移散落在渲染代码里。

### 3.3 校验与收尾

1. 在自检脚本中为该角色添加专属断言区（数据完整性、精灵表可加载、技能行为的基本回归），照已有角色的模式写。
2. 若有新特效，补入渲染层特效表。
3. 跑 `npm run check`，全绿后由维护者目视验收（进浏览器打一场，看选人、动表、技能演出、音效）。
4. 更新必要的展示文案后提交。**未经要求不要主动 commit / push**，交由维护者确认。
